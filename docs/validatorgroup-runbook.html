The one rule that matters

Almost every confusing failure with this module traces back to one distinction: whether a change lives in genesis state or in runtime config. Get this wrong and edits appear to save correctly while having no effect at all.

Genesis · full reset

genesis.json

Admin address, validator whitelist, denom metadata, active precompiles. Applied only by InitGenesis, which runs once, at chain height 0.

Runtime · restart only

app.toml · config.toml

JSON-RPC enable, bind address, mempool type. Read fresh on every start, so a plain restart is enough — never reset for these.

Live · no restart

Precompile calls

Adding and removing whitelisted validators are ordinary transactions against the running chain. Nothing to restart.

Any genesis edit needs a full reset before the next start, or it is silently ignored:

reset + restartdestroys chain history
sudo systemctl stop evmd
evmd comet unsafe-reset-all --home ~/.evmd
sudo systemctl start evmd

Never do this instead

Use evmd comet unsafe-reset-all, not rm -rf ~/.evmd/data. The raw wipe deletes priv_validator_state.json without regenerating it, and the node refuses to start with no such file or directory.

Admin can only be set at genesis

SetAdmin is called from exactly one place — InitGenesis. There is no Msg service and no setAdmin precompile method; the module exposes only admin, addValidatorAddress, removeValidatorAddress and isWhitelisted.

Before production

Once the chain carries real history, the admin address can never be changed. The only mechanism — reset and re-edit genesis — destroys every block, balance and validator on the chain.

If admin rotation could ever be needed (a lost key, an org handoff), add a setAdmin(address) method gated by requireAdmin, following the same pattern as addValidatorAddress. Treat it as a launch blocker, not a nice-to-have.

01

First-time node setup

Genesis · full reset

Run once, when bootstrapping a fresh chain. The sub-steps are ordered — each depends on the one before it.

1aInitialise the chain

bashon the node host
evmd init my-validator --chain-id mytestnet_9000-1 --home ~/.evmd
evmd keys add validator --keyring-backend test --home ~/.evmd

evmd genesis add-genesis-account \
  $(evmd keys show validator -a --keyring-backend test --home ~/.evmd) \
  10000000000000000000000stake --keyring-backend test --home ~/.evmd

evmd genesis gentx validator 1000000000000000000stake \
  --chain-id mytestnet_9000-1 --keyring-backend test --home ~/.evmd

evmd genesis collect-gentxs --home ~/.evmd

1bFour genesis edits, all required before first start

None of these apply retroactively. Missing any one of them produces a startup panic or a precompile that silently cannot be reached.

bashgenesis.json
# set the module admin (prompts if no address is passed)
./scripts/setup_admin.sh 0xYourAdminEvmAddress

GENESIS=~/.evmd/config/genesis.json

# whitelist the gentx validator, or InitGenesis rejects its own gentx —
# the ante handler blocks MsgCreateValidator for anyone not whitelisted,
# and that check runs during genesis replay too
VAL_ADDR="cosmosvaloper1..."   # evmd keys show validator --bech val -a
jq --arg val "$VAL_ADDR" '.app_state.validatorgroup.validators += [$val]' \
  "$GENESIS" > "$GENESIS.tmp" && mv "$GENESIS.tmp" "$GENESIS"

# bank denom metadata for the EVM denom — x/vm panics without it
EVM_DENOM=$(jq -r '.app_state.evm.params.evm_denom' "$GENESIS")
DISPLAY_DENOM="display${EVM_DENOM}"
jq --arg base "$EVM_DENOM" --arg display "$DISPLAY_DENOM" '
  .app_state.bank.denom_metadata += [{
    description: ("Native denom metadata for " + $base),
    denom_units: [
      {denom: $base, exponent: 0, aliases: []},
      {denom: $display, exponent: 18, aliases: []}
    ],
    base: $base, display: $display, name: $base,
    symbol: ($base | ascii_upcase)
  }]' "$GENESIS" > "$GENESIS.tmp" && mv "$GENESIS.tmp" "$GENESIS"

# activate the precompile — registered in code, but gated off by default
jq '.app_state.evm.params.active_static_precompiles +=
    ["0x0000000000000000000000000000000000000808"] |
    .app_state.evm.params.active_static_precompiles |= sort' \
  "$GENESIS" > "$GENESIS.tmp" && mv "$GENESIS.tmp" "$GENESIS"

1cHost configuration

Runtime · restart only
bashapp.toml · config.toml
# CometBFT mempool must be "app" when the EVM app-side mempool is on
sed -i '/^\[mempool\]/,/^\[/ s/^type = .*/type = "app"/' ~/.evmd/config/config.toml

# JSON-RPC is disabled by default — nothing listens on 8545 until this is set
sed -i '/^\[json-rpc\]/,/^\[/ s/^enable = .*/enable = true/' ~/.evmd/config/app.toml

In the systemd unit, pass --chain-id explicitly so startup never depends on client.toml carrying it:

ini/etc/systemd/system/evmd.service
ExecStart=/home/ekoios/go/bin/evmd start \
  --home /home/ekoios/.evmd --chain-id mytestnet_9000-1

1dStart and verify

bashhealth check

sleep 5

# is the chain producing blocks?

  --data '{"jsonrpc":"2.0","method":"eth_blockNumber","params":[],"id":1}' \
  http://127.0.0.1:8545

A healthy result reads admin: 0xYourAdminEvmAddress. Anything else means one of the genesis edits above did not take — see Troubleshooting.

02

Reaching the node from another machine

Runtime · restart only

By default the RPC binds to 127.0.0.1 and only accepts connections from the node itself. To use it from a laptop or another host, bind it wider.

bashno reset needed
sudo systemctl stop evmd
sed -i 's|^address = "127.0.0.1:8545"|address = "0.0.0.0:8545"|' ~/.evmd/config/app.toml
sed -i 's|^ws-address = "127.0.0.1:8546"|ws-address = "0.0.0.0:8546"|' ~/.evmd/config/app.toml
sudo systemctl start evmd

# scope the firewall to a trusted source, not the whole internet
sudo ufw allow from <trusted-subnet-or-IP> to any port 8545 proto tcp

Exposure

Binding to 0.0.0.0 exposes write methods such as eth_sendRawTransaction to anyone who can reach the port. Avoid a blanket ufw allow 8545/tcp on any host with public exposure, and leave json-rpc.allow-insecure-unlock and rpc.unsafe off unless specifically needed.

From the remote machine, point the scripts at the node and install the one dependency they need:

bashclient side
python3 -m pip install web3
export VALIDATOR_RPC_URL="http://10.2.12.177:8545"
./scripts/check_admin.sh
03

Daily operations

Live · no restart

Ordinary transactions against the running chain. Each script prompts for what it needs, so they can be run with no arguments at all.

check_admin.sh

read

Prints the address currently holding admin rights.

is_whitelisted.sh

read

Reports whether one address is in the validator group.

add_validator.sh

write · admin only

Adds an address to the whitelist, then confirms the change landed.

remove_validator.sh

write · admin only

Removes an address from the whitelist, then confirms the change landed.

bashinteractive
$ ./scripts/add_validator.sh
? RPC URL [http://127.0.0.1:8545]: http://10.2.12.177:8545
? Validator EVM address to ADD to the whitelist: 0x0466...aD33D
? Admin private key (hidden):
tx_hash: 0x52e9eebc455f46cc13f7011ebd9fb634ab521d5dd22d1a86046c73543219ba31
confirmed: 0x8545...56D3 is now whitelisted (block 5523)

Private key input is hidden — never echoed, never written to shell history. Addresses are validated as they are typed.

Three ways this precompile fails quietly

The write scripts guard against each of these, because none of them surface as an error on their own:

  • No-op writes report success. RemoveValidator calls store.Delete unconditionally and the precompile returns true either way. Removing an address that was never whitelisted therefore succeeds on-chain, costs gas, and changes nothing. The scripts check current state first and send no transaction.
  • Non-admin callers still get a transaction. The revert happens during execution, so the transaction is mined with a hash and a failed status. The scripts compare the signer against admin() and refuse before broadcasting, naming both addresses.
  • A transaction hash is not a result. A mined transaction can still have reverted, so the scripts wait for the receipt, require status == 1, then re-read the whitelist to prove the state actually changed.

Removal is not deregistration

remove_validator.sh clears the whitelist entry only. It does not unbond or jail a validator that is already active — the ante handler blocks new MsgCreateValidator messages, nothing more. An already-bonded validator keeps producing blocks and earning rewards until it is separately unbonded.

Arguments and environment variables skip the matching prompt, so the scripted form is unchanged:

bashnon-interactive
export VALIDATOR_RPC_URL="http://<node-ip>:8545"
export VALIDATOR_PRIVATE_KEY="<admin private key>"

./scripts/add_validator.sh    0xValidatorEvmAddress
./scripts/is_whitelisted.sh   0xValidatorEvmAddress
./scripts/remove_validator.sh 0xValidatorEvmAddress

Where stdin is not a terminal — CI, cron, a piped shell — a missing required value exits with code 2 and a clear message rather than hanging on a prompt.

04

Smoke test

Live · no restart

test_validatorgroup.sh exercises the full cycle with real assertions: check admin, confirm the target is not already whitelisted, add it, confirm, remove it, confirm again. It exits non-zero if any step fails.

bashprompts for everything
$ ./scripts/test_validatorgroup.sh
? RPC URL [http://127.0.0.1:8545]:
? Admin EVM address: 0x...
? Admin private key (hidden):
? Test validator EVM address (will be added, then removed): 0x...

Pick a throwaway address

The test address must not already be a real whitelisted validator — the run ends by removing it. If the pre-condition check finds it already in the group, the script aborts before touching anything rather than risk deregistering a live validator.

The optional set-admin step is off unless explicitly requested and confirmed by typing RESET, because it wipes all chain history. Setting VALIDATOR_RPC_URL, ADMIN_ADDR, ADMIN_PRIVATE_KEY and TEST_VALIDATOR_ADDR pre-fills the prompts for unattended runs.

05

Troubleshooting

When evmd start exits with a failure, read the real error first — the flag dump that systemd prints is noise, and the actual cause is the last line before it:

bashfind the real error
journalctl -u evmd -n 60 --no-pager | cat

These are the failures that show up on a fresh setup, roughly in the order they surface:

ErrorCause and fix
comet-bft has invalid config.toml:mempool.type [mempool] type must be "app" when the EVM mempool is enabled. Restart only.
invalid chain-id on InitChain; expected: Chain ID resolved to empty — it is absent from both the flag and client.toml. Pin --chain-id in the systemd unit.
open .../priv_validator_state.json: no such file The data directory was deleted with rm -rf instead of reset. Run evmd comet unsafe-reset-all to regenerate it.
error initializing evm coin info: denom metadata … could not be found No bank.denom_metadata entry matching evm_denom. Add it, then reset — see step 1b.
validator address is not authorized in organization whitelist The gentx validator is missing from validatorgroup.validators, so genesis rejects its own gentx. Add it, then reset — see step 1b.
Connection refused  (on 8545) JSON-RPC is disabled, which is the default. Set enable = true under [json-rpc]. Restart only.
Could not transact with/call contract function The precompile address is not in evm.params.active_static_precompiles, so the call reaches nothing. Add it, then reset — see step 1b.
ModuleNotFoundError: No module named 'web3' Client-side only. Run python3 -m pip install web3 on the machine running the scripts.

Which fix needs which action

Anything touching genesis.json needs unsafe-reset-all and a restart before it takes effect. Anything in app.toml or config.toml needs only a restart. Applying a genesis fix without the reset is the single most common reason a correct-looking edit appears to do nothing.
